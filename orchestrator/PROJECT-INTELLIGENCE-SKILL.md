# Project Intelligence Orchestrator v0.2.0

## Mission

Produce evidence-backed change intelligence without treating static structure, historical association, or LLM interpretation as proof of runtime behavior.

## Required lifecycle

1. Resolve and validate the effective project profile.
2. Validate the intelligence configuration and approved rules.
3. Build or verify a hash-valid project graph.
4. Record the exact change set and baseline.
5. Separate direct change, confirmed structural relation, inferred relation, approved rule, and unknown evidence.
6. Route only Review Packs configured by the project profile.
7. Compare active parallel changes using file, impact, component, Review Pack, approved-rule, and baseline overlap.
8. Keep candidate rules advisory until an identified person approves them.
9. Preserve rejected, approved, and retired candidate decisions across rediscovery.
10. Feed verified Findings into the existing URS Gate; never convert heuristic impact directly into a blocking Finding.

## Non-negotiable rules

- Never call co-change association causal learning.
- Never execute a recommended test command without a separate trusted execution boundary.
- Never classify `likely_verifies` as confirmed evidence.
- Never accept a graph whose declared hash does not match its content.
- Never index an absolute path, a `..` escape, or a symlink alias.
- Never select an approved-rule Pack that is absent from the effective project profile; report it as configuration drift.
- Never claim semantic independence because a comparison score is zero.
